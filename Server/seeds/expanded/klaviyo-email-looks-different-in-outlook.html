Short answer: Klaviyo emails break in Outlook mainly because classic Outlook uses Microsoft Word to render HTML and ignores much modern CSS. Common symptoms are images at full size, misaligned columns, Times New Roman text, cut-off lines and square buttons. Most can be fixed inside Klaviyo with set image widths, simpler blocks and web-safe fallback fonts; persistent problems need a custom-coded template.

Why Outlook Is Different

Gmail, Apple Mail and most phone apps use browser-like engines. Classic Outlook for Windows does not. It uses the Word rendering engine, which supports only a small part of CSS. It ignores things like max-width, border-radius, background images set in CSS, and many margin and padding rules on non-table elements. Klaviyo's drag-and-drop blocks try to handle this, but some settings and custom content still slip through.

New Outlook and Outlook on the web use a browser engine, so they behave better, but they have their own quirks. For the full background, see new vs classic Outlook and why new Outlook breaks HTML email.

Images at full size

If you upload a 2400px wide image and don't set a width, Outlook may show it at its real size, far wider than the email. In the image block, set a fixed width (for example 600px for full width or 280px in a two-column row). Also resize the file before you upload. A smaller file loads faster and Outlook respects the width attribute more reliably. In custom code it should look like <img src="hero.jpg" width="600" style="display:block; width:100%; max-width:600px; height:auto" alt="New spring collection">.

Times New Roman fallback

Outlook does not load most web fonts. When the font stack is wrong, it falls back to Times New Roman. Always end your font stack with a safe font, for example font-family: 'Poppins', Arial, Helvetica, sans-serif. In custom templates, some developers also add an MSO-only style so Outlook uses Arial directly.

Cut-off or overlapping text

Outlook handles unitless or very tight line heights badly. Use pixel values that are at least 1.4 times the font size, for example 16px text with 24px line height. Avoid negative margins and very small padding around headlines.

Buttons that lose their shape

Rounded corners and padding on a link do not work in classic Outlook. Klaviyo's button block uses Outlook-safe code, so use it rather than styling a text link. In a custom template, use a bulletproof email button built with a table cell or VML.

Tips Inside Klaviyo

  • Preview with Klaviyo's inbox preview and send a real test to an Outlook account. Previews help, but a real send catches things previews miss.
  • Avoid pasting HTML into text blocks; it can carry styles Outlook can't read. Paste as plain text and style inside the editor.
  • Keep image text minimal; Outlook may block images by default. See why email images don't show.
  • Check dark mode, which Outlook applies aggressively. Use logos with a transparent background and a light outline if needed.
  • Avoid background images in blocks when the message depends on them. Classic Outlook may drop them. See Outlook background images.
  • Keep section widths consistent. Mixing 600px and 640px sections can cause odd gaps.

A Simple Testing Routine

  1. Build the email in Klaviyo and check the web preview.
  2. Run Klaviyo's inbox preview for Outlook 2016, 2019 and Microsoft 365 on Windows.
  3. Send a real test to a classic Outlook for Windows account and to new Outlook.
  4. Check at 100% and 125% Windows display scaling, as scaling can change spacing.
  5. Turn images off and check the email still makes sense.
  6. Switch Outlook to dark mode and check logos, text and buttons.

What a Coded Outlook Fix Looks Like

When a template is coded by hand, a developer adds a few Outlook-only pieces that Klaviyo's blocks cannot always add for you. These sit inside conditional comments, so only classic Outlook reads them:

  • Ghost tables that hold columns at fixed widths, so a two-column row stays side by side.
  • VML code for background images and rounded buttons.
  • An MSO font rule that forces Arial when a web font is used elsewhere.
  • Line-height rules such as mso-line-height-rule:exactly, so text is not clipped.
  • Table cell padding instead of margins, since Outlook ignores most margins.

For example, a DPI fix helps when Windows display scaling is set above 100%, which can make images and tables grow unevenly. A developer adds an <o:OfficeDocumentSettings> block in the head with a PixelsPerInch value of 96. It is invisible to other clients and fixes a problem that is hard to spot until a customer reports it.

None of this is something you should need to think about every week. Once it is inside a saved template, every campaign built from it gets the same protection.

Frequently Asked Questions

Why does my Klaviyo email look fine in Gmail but not Outlook?

Classic Outlook uses Microsoft Word to render emails, which ignores much of the CSS that Klaviyo's blocks and custom code rely on.

How do I test Klaviyo emails in Outlook?

Use Klaviyo's inbox preview and send a test to a real classic Outlook for Windows account. Also check new Outlook and Outlook on the web.

Can I fix Outlook issues without coding?

Many, yes: set image widths, simplify split blocks, use fallback fonts and Klaviyo's button block. Deeper issues need a coded template.

Why is my text showing in Times New Roman in Outlook?

Outlook can't load your web font and has no safe fallback. Add Arial or Helvetica at the end of your font stack.

Does Outlook on Mac have the same problems?

No. Outlook for Mac uses a browser-like engine, so it usually renders closer to Apple Mail. Classic Outlook for Windows is the main problem.
