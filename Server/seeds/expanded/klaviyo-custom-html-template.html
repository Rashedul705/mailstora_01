Short answer: Klaviyo supports three kinds of templates: drag-and-drop, full HTML, and hybrid. A full HTML template gives total design control, but only people who can code can change it. The best option for most stores is a hybrid template or HTML with editable regions: the layout is custom-coded, while text, images and buttons stay editable in Klaviyo's editor.

Hybrid sits in the middle: a developer codes the structure, and marketers edit content visually. How to Add a Custom HTML Template

  1. Go to Content, Templates in Klaviyo and create a new template.
  2. Choose the option to start from HTML (or code), then paste or upload your HTML.
  3. Upload images to Klaviyo's image library or host them on a stable CDN, and use full https:// URLs.
  4. Save, preview, and send tests to real inboxes.
  5. Use the template in a campaign or flow email.

Make sure your HTML is already email-safe before you import: table-based layout, inline styles, Outlook conditional comments and alt text on images. If it was built from a Figma design, our Figma to HTML email handoff checklist helps avoid surprises.

How to Make a Custom Template Editable

  1. Use editable regions: mark text and images with Klaviyo's editable attributes so they open in the visual editor. For example, a text area can be marked with <div class="editable" data-klaviyo-region="true">...</div>-style markup; check Klaviyo's docs for the exact current syntax.
  2. Build reusable sections: header, hero, product grid, testimonial and footer as separate blocks.
  3. Save universal blocks for the header and footer so one change updates every email.
  4. Use dynamic product feeds instead of hard-coded products, so best sellers and recommendations stay current.
  5. Add fallbacks for personalisation, for example {{ first_name|default:'there' }}.

Using event data in flows

In flows, the trigger event carries data you can loop over. In an abandoned cart email, for example, you can show each item with a loop like {% for item in event.Items %} ... {{ item.ProductName }} ... {% endfor %}. The exact field names depend on your integration, so check a preview with a real test profile. Always design a fallback for when an image or price is missing.

Common Problems

  • The editor changes your code: editing HTML in the drag-and-drop editor can rewrite it. Keep code edits in the HTML editor.
  • Layout breaks in Outlook: the template needs table-based code and Outlook fixes. See why emails break in Outlook and Klaviyo emails in Outlook.
  • Emails get clipped in Gmail: keep the HTML under 102 KB. See how to fix Gmail clipping.
  • Images look wrong in dark mode: see our dark mode email design guide.
  • Template tags show as raw text: a typo in {{ }} or {% %} syntax, or smart quotes pasted from a document. Retype quotes as plain straight quotes.
  • Broken images after import: relative image paths. Use absolute URLs.

Build Checklist

  • Max width 600 to 640px, table-based, role="presentation" on layout tables.
  • All key styles inline; media queries only as an extra.
  • Web-safe fallback fonts in every font stack.
  • Bulletproof buttons coded as live text.
  • Editable regions on every text, image and button that marketers will change.
  • Header and footer as universal blocks.
  • Personalisation tags with defaults.
  • Unsubscribe and address tags present in the footer.
  • Tested in Outlook, Gmail, Apple Mail and mobile. See our email testing checklist.

Before any code is written, list the emails you send and the sections they share. Most ecommerce brands need a small set of sections that can be mixed and matched:

With six to ten well-built sections, a team can create most campaigns without new code. It also keeps file size lower, because each section is lean and tested once.

Keep a short guide for the marketing team explaining which section to use for what, the recommended image sizes and the character limits for headlines. That small document saves many broken layouts later.

Maintaining the Template Over Time

A template is not finished on launch day. Email clients change, your brand evolves and new sections are needed. A few habits keep it healthy:

  • Keep a master copy of the HTML outside Klaviyo, in a shared folder or code repository, so you can always roll back.
  • Change universal blocks with care. An edit to the footer updates every email that uses it, including live flows.
  • Retest after big client updates, such as changes to new Outlook or Gmail, and after adding any new section.
  • Review flow emails every few months so old designs and expired offers do not keep sending.

Small, regular checks are far cheaper than a full rebuild when something breaks during a busy sale week.

Frequently Asked Questions

Can I use custom HTML in Klaviyo?

Yes. You can create a template from HTML in Klaviyo, or build a hybrid template with custom-coded sections that remain editable.

Will a custom HTML template work with Klaviyo's drag-and-drop editor?

Only if it is built for it. Templates with editable regions or hybrid blocks open in the visual editor; plain HTML templates only open in the code editor.

Can dynamic product blocks be used in a custom template?

Yes. Custom templates can include Klaviyo product feeds and event data, for example the items left in a cart.

Why do my personalisation tags show as raw text?

Usually a syntax error or curly quotes pasted from a document. Check the brackets and retype quotes as straight quotes.

Should flows and campaigns use the same template?

They should share the same design system, header and footer, so every email feels consistent, even if the sections differ.
