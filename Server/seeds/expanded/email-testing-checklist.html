Short answer: before sending any email, check that it renders correctly in Outlook, Gmail, Apple Mail and on mobile; that it stays under Gmail's 102 KB limit; that it looks right in dark mode; that every link, merge tag and image works; that it is readable and accessible; and that your platform settings (subject, preheader, audience, unsubscribe) are correct.

This is the same checklist we use for every email in our email testing and QA service. Copy it into your own pre-send routine.

Once an email is sent, you cannot take it back. A broken button, a wrong price or a layout that falls apart in Outlook reaches every subscriber at once. A short, repeatable checklist catches most of these problems in minutes. The 25 points below are grouped so you can work through them in order, from how the email looks to how it is sent.

Rendering (1–6)

  1. Classic Outlook for Windows shows the layout correctly (columns, spacing, buttons).
  2. New Outlook and Outlook on the web look the same.
  3. Gmail on web, Android and iOS shows the full design.
  4. Apple Mail and iOS Mail render correctly.
  5. Yahoo Mail and other clients your audience uses are checked.
  6. Web fonts fall back to a clean system font where unsupported.

Classic Outlook for Windows uses Microsoft Word to render HTML, which is why it breaks layouts other clients handle well. New Outlook uses a more modern engine, so the two can look quite different. See new Outlook vs classic Outlook rendering for what changes between them.

For font fallback, always list a safe system font after your web font:

font-family: 'Inter', Arial, Helvetica, sans-serif;

Mobile (7–9)

  1. Columns stack neatly on a phone.
  2. Text is at least 14 px and buttons at least 44 px tall.
  3. Images scale down without stretching or cropping key content.

Most people read email on a phone, so mobile checks matter as much as desktop ones. Open the test on a real phone, not only a resized browser window. If columns refuse to stack, our guide on responsive email not working on mobile covers the usual causes, such as missing media queries or fixed widths.

Size and Dark Mode (10–12)

  1. The HTML is under 102 KB, so Gmail does not clip it. See how to fix Gmail clipping.
  2. The email looks right in dark mode in Gmail, Outlook and Apple Mail. See our dark mode email design guide.
  3. Logos and icons stay visible on dark backgrounds.

A quick way to check size is to save the final HTML as a file and look at its size on disk. Remember that your platform may add tracking code when it sends, so aim to stay well under the limit, not just under it. For dark mode, a dark logo on a transparent PNG is the most common problem; a thin light outline or a light background behind the logo usually fixes it.

Links and Content (13–18)

  1. Every link and button goes to the right page.
  2. UTM or tracking parameters are correct and consistent.
  3. Merge tags such as first name show real values, with a fallback if empty.
  4. Dynamic product or order blocks show the right items.
  5. Prices, dates, codes and offer terms are correct.
  6. Spelling and grammar are checked.

Merge tags need a default so an empty field does not leave an awkward gap. In Klaviyo, for example, a first name with a fallback looks like this:

{{ first_name|default:'there' }}

Click every link in the real test email, not in the editor preview. Tracking wrappers are added at send time, and that is where broken links often show up. Buttons should be built from code so they still work when images are off; see bulletproof email buttons.

Images and Accessibility (19–22)

  1. Every image has meaningful alt text; decorative images have empty alt.
  2. The email still makes sense with images turned off.
  3. Text and button colours have enough contrast.
  4. Important text is live text, not only inside images.

A decorative image should use an empty alt attribute, like alt="", so screen readers skip it. A content image needs alt text that says what it shows or what it offers. For more on screen readers, heading order and contrast, read our accessible email design guide.

Platform and Deliverability (23–25)

  1. Subject line and preheader text are set and fit on mobile.
  2. The right list or segment is selected, and send time and time zone are correct.
  3. The unsubscribe link and company address are in the footer and work.

These last three checks are easy to skip because they live in the platform settings, not the design. They also cause some of the most visible mistakes, such as sending a VIP offer to the whole list or sending at 3 a.m. in your main market.

Common Testing Mistakes

  • Testing only in the editor preview. Previews are not real email clients. Always send real tests.
  • Checking one Outlook version. Classic Outlook, new Outlook and Outlook on the web behave differently.
  • Skipping images-off. Many work inboxes block images by default.
  • Retesting nothing after a small change. A last-minute text edit can push a file over the size limit or break a table.
  • One person doing everything. A second pair of eyes catches wrong prices and dates much more often.

Frequently Asked Questions

Which email clients should I test in?

At minimum: classic Outlook for Windows, Gmail (web and mobile), Apple Mail and iOS Mail. Then add the clients your own audience uses most, which you can see in your email platform's reports.

How do I test an email in Outlook without Windows?

Use an email testing tool that renders screenshots in real Outlook versions, or send a test to a colleague who uses classic Outlook for Windows.

How long does email testing take?

With a checklist and a testing tool, 15 to 30 minutes per email. A well-built template makes each new send faster to check.

Do I need to retest every campaign if I use the same template?

Yes, but it is faster. The layout is already proven, so focus on links, content, images, merge tags and platform settings. Do a full rendering check after any template change.

Is a testing tool enough on its own?

It is a big help, but also send a real test to Gmail and Outlook and open it on a phone. Real inboxes show tracking links, images-off views and dark mode more reliably.
