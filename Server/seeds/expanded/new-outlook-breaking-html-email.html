Short answer: New Outlook processes your email before showing it. It can rename CSS classes, remove some head styles, change spacing and apply its own dark mode colours, so emails that depend on classes, embedded styles or tight spacing tricks are most at risk. The fix is to inline all important styles, avoid relying on class selectors, and test in new Outlook and Outlook on the web.

What Is New Outlook?

New Outlook for Windows is Microsoft's replacement for the classic desktop app. Unlike classic Outlook, which renders with Microsoft Word, new Outlook is built on the same web technology as Outlook on the web. That sounds like good news, and in many ways it is: modern CSS such as border-radius and max-width works much better. But it also means your email goes through a web-style sanitiser that rewrites the HTML before display. At the time of writing, many businesses run classic and new Outlook side by side, so you need to support both.

For a side-by-side comparison of the two engines, read new Outlook vs classic Outlook.

What Commonly Breaks

  • Head styles ignored or changed. Class names can be prefixed, so some selectors stop matching. A rule like .hero-title { font-size:32px } may never reach the element.
  • Media queries unreliable. Mobile layouts may not switch as expected, especially in narrow reading panes.
  • Spacing shifts. Default margins on paragraphs and headings can appear if you didn't reset them inline. Emails suddenly look loose or uneven.
  • Dark mode colours. Backgrounds and text can be adjusted, sometimes making logos or light text hard to see. See our dark mode guide.
  • Old MSO-only tricks. Layouts that only worked because of Word quirks can fall apart in the web engine, for example spacing done with empty paragraphs or mso-line-height-rule hacks without a proper fallback.
  • Unsupported selectors. Attribute selectors, sibling selectors and some pseudo-classes may be removed.

How to Fix It

  1. Inline critical styles: colours, fonts, widths, padding and margins on each element. Use an inliner as the last build step so you can still write clean CSS while working.
  2. Reset margins inline on p and heading tags, for example style="margin:0 0 16px".
  3. Use the hybrid method for columns so layouts stack without media queries. See responsive email fixes.
  4. Keep Outlook-only code in conditional comments so it only affects classic Outlook.
  5. Test in three places: classic Outlook, new Outlook and Outlook on the web.

Example: before and after

This relies on a class and will often break:

<style>.intro{font-size:18px;color:#333;margin:0}</style> ... <p class="intro">Welcome back</p>

This keeps working even if the head styles are changed:

<p style="font-family:Arial,Helvetica,sans-serif; font-size:18px; line-height:26px; color:#333333; margin:0 0 16px">Welcome back</p>

You can keep the class too, for media query overrides. But the default look should come from inline styles.

Example: Outlook-only code

Classic Outlook still needs ghost tables to hold columns. Wrap them so other clients skip them:

<!--[if mso]><table role="presentation" width="600"><tr><td width="300"><![endif]-->

New Outlook ignores this block, so it will not interfere with its web-based rendering.

Why It Looks Right, Then Changes

Some users report an email looking correct for a moment and then shifting. That happens when the client finishes processing styles after the first display. If your layout depends on head styles alone, the second pass can undo it. Inline styles solve most of these cases, because there is nothing left for the second pass to remove.

Common Mistakes

  • Deleting classic Outlook fixes. Classic Outlook is still widely used. Keep the fixes, just isolate them.
  • Testing only in Outlook on the web. It is close to new Outlook, but not always identical. Test both.
  • Using spacer paragraphs. Empty <p>&nbsp;</p> tags change height between clients. Use padding on table cells instead.
  • Relying on a template builder's preview. Real sends reveal processing that previews do not.

A Real-World Scenario

An agency sends a monthly newsletter for a client whose staff moved to new Outlook. The template was built with a big style block and short class names. After the switch, headings lost their size, paragraphs gained extra space and the two-column article section stayed side by side in a narrow reading pane. The fix was to inline all base styles, add margin resets and switch the columns to a hybrid layout. Classic Outlook ghost tables stayed in place inside conditional comments. The same template then looked consistent in classic Outlook, new Outlook, Gmail and Apple Mail.

Dark Mode in New Outlook

New Outlook can change colours when a reader uses a dark theme. Light backgrounds may turn dark and dark text may turn light. Usually this is fine, but some elements suffer:

  • Dark logos on transparent backgrounds can disappear on a dark background. Add a thin light outline or a light padded background around the logo.
  • Text inside images does not change colour, so it can look out of place next to inverted live text.
  • Brand colours may be shifted slightly. Check that buttons still have strong contrast.

Test every template in dark mode in new Outlook, classic Outlook and Outlook on the web. They do not always apply the same changes.

A Simple Build Order

If you are building a new template that must work across all Outlook versions, this order keeps things simple:

  1. Build a single-column layout in tables with inline styles.
  2. Add hybrid columns where needed, using display:inline-block and max-width.
  3. Add ghost tables and VML for classic Outlook inside conditional comments.
  4. Add media queries last, only for polish.
  5. Inline, minify and check the file size.
  6. Test in all three Outlook versions, plus Gmail and Apple Mail.

Building in this order means that if a client strips something, the email falls back to a layout that still works, rather than breaking completely.

Frequently Asked Questions

Why does my email look different in new Outlook?

New Outlook processes email HTML before display and can change classes, head styles, spacing and dark mode colours.

Does new Outlook support media queries?

Support is limited and inconsistent. Use hybrid layouts that work without media queries, and treat media queries as an extra.

Should I remove my classic Outlook fixes for new Outlook?

No. Keep them in conditional comments. New Outlook ignores them, and classic Outlook still needs them.

Is new Outlook the same as Outlook on the web?

They are closely related and render in a similar way, but small differences can appear. Test in both.

Why is there extra space between paragraphs in new Outlook?

Default margins are applied when your head styles are removed or changed. Set margins inline on every paragraph and heading.
