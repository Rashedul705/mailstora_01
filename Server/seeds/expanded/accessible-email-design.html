Short answer: An accessible email can be read and used by people with low vision, colour blindness, or who use screen readers. The main changes are useful alt text on images, text contrast of at least 4.5:1, real headings, body text of 14 to 16 px or larger, clear link text, live text instead of text in images, and layout tables marked with role="presentation".

Why Accessibility Matters

  • Millions of people use screen readers or zoom to read email.
  • Accessible emails are easier for everyone to read, especially on phones, in bright sunlight or when images are blocked.
  • In many regions, accessibility is a legal expectation for businesses. Check the rules that apply where you sell.
  • Clear structure and live text also help your email survive image blocking and dark mode.

Content Checklist

  1. Alt text: describe the purpose, like "Free shipping on orders over $50". Use empty alt (alt="") for decorative images, such as dividers and background shapes.
  2. Link text: say where the link goes. "Read the dark mode guide" beats "click here".
  3. Short paragraphs and plain language. One idea per paragraph.
  4. Don't rely on colour alone to show meaning, such as sale prices; add words or icons, like "Now $30, was $45".
  5. Clear subject line and preheader. Screen reader users hear these first, so make them useful.
  6. Avoid emoji overload. Screen readers read each emoji's name aloud, which can get long.

Design Checklist

  1. Contrast: at least 4.5:1 for body text and 3:1 for large headings. Light grey text on white is a common failure.
  2. Text size: 14 to 16 px body text, 1.5 line height.
  3. Left-aligned text for long paragraphs; avoid long centered text blocks.
  4. Buttons: large, high-contrast and coded as live text. Aim for a tap area of about 44px high. See bulletproof buttons.
  5. Dark mode: check contrast in both modes. See our dark mode guide.
  6. Spacing: leave room between links so they are easy to tap.
  7. Motion: keep GIFs subtle and avoid fast flashing.

Code Checklist

  • Add lang="en" (or your language) on the html tag.
  • Use real h1, h2 and p tags, not styled spans.
  • Add role="presentation" to layout tables so screen readers don't announce rows and columns.
  • Keep reading order logical when columns stack on mobile.
  • Set a title tag that matches the subject.
  • Use real data tables with th headers only for actual data, like an order summary.

Code example

A layout table and heading done well:

<table role="presentation" width="100%" cellpadding="0" cellspacing="0" border="0"><tr><td style="padding:24px"><h1 style="margin:0 0 12px; font-family:Arial,sans-serif; font-size:28px; line-height:34px; color:#1a1a1a">Your order is on its way</h1></td></tr></table>

Compare this with a <span style="font-size:28px"> used as a heading. It looks the same, but a screen reader user can't jump to it with heading navigation.

Common Mistakes

  • The whole email as one image. Screen readers get almost nothing, and image blocking hides the message. See why email images don't show.
  • Alt text that repeats the file name or says "image of".
  • Many "Shop now" links with the same text going to different pages. Make each one specific, such as "Shop trainers".
  • Tiny footer text in light grey. Legal text still needs to be readable.
  • Columns that stack in the wrong order on mobile, so the image appears after its description.

Test It

Turn images off, zoom to 200%, and listen to the email with a screen reader (VoiceOver on Mac and iPhone, or NVDA on Windows). Check contrast with any free contrast checker. Accessibility checks are part of our email testing checklist.

  1. Images off: does the email still make sense?
  2. Zoom 200%: does text reflow without sideways scrolling?
  3. Screen reader: are headings, links and reading order clear?
  4. Dark mode: is every piece of text still readable?

A Real-World Scenario

A retailer sends a sale email where the main offer, the dates and the discount code are all inside one hero image. A customer using a screen reader only hears "sale banner" and a "Shop now" link. When the email was rebuilt, the headline, dates and code became live text on a solid background, the image got a short descriptive alt, and the button text became "Shop the spring sale". The email looked almost the same to sighted readers, but now worked with images off and with a screen reader.

Accessibility in Your Email Platform

Most email platforms let you add alt text and use headings, but you need to use these features on purpose. A few tips:

  • Klaviyo, Mailchimp and HubSpot all have an alt text field on image blocks. Fill it every time, or leave it empty on purpose for decorative images.
  • Use the editor's heading styles instead of making normal text bigger and bold.
  • Check the button block's colours against a contrast checker before saving it as a brand default.
  • Save accessible sections as reusable blocks so every new campaign starts from a good base.

If your template is custom-coded, the developer should set the lang attribute, heading tags and presentation roles once, so your team only needs to focus on alt text and link wording.

Quick Priority List

If you can only fix a few things this week, start here:

  1. Move key text out of images and into live text.
  2. Add meaningful alt text to every important image.
  3. Fix low-contrast text, especially grey text and footer text.
  4. Rewrite vague link text.
  5. Add role="presentation" to layout tables.

These five changes cover most of the problems readers hit, and none of them change the look of your brand.

Accessibility in Email Signatures and Plain Text

Accessibility is not only for marketing emails. Staff email signatures are often a single image with the name, phone number and logo baked in. That means a screen reader hears nothing useful, and the phone number cannot be tapped. A better signature uses live text for contact details and a small logo with alt text. Frequently Asked Questions

What makes an email accessible?

Useful alt text, good colour contrast, readable text size, real headings, clear link text and live text instead of text in images.

What is role="presentation" in email?

It tells screen readers that a table is used only for layout, so they read the content without announcing table rows and columns.

What contrast ratio should email text have?

At least 4.5:1 for normal text and 3:1 for large text, following WCAG guidelines.

Should decorative images have alt text?

No. Use an empty alt attribute, alt="", so screen readers skip them. Do not remove the attribute completely.

How do I test an email with a screen reader?

Use VoiceOver on a Mac or iPhone, or NVDA on Windows. Open the email in a real client and listen from top to bottom.
