Short answer: a bulletproof email button is made from HTML and CSS, not an image, so it shows even when images are blocked. The most reliable method is a table cell with a background colour and a link inside it with padding. For rounded corners in Outlook, add a VML version inside Outlook-only comments. Make buttons at least 44 px tall so they are easy to tap.

Why Image Buttons Fail

Many email builders still let you drop in a picture of a button. It looks fine in the editor, but it causes real problems in the inbox.

  • When images are blocked, the button disappears and so does your click. Some Outlook setups and corporate filters block images by default.
  • Text inside an image cannot be recoloured in dark mode and is not read by screen readers.
  • Image buttons can look blurry on high-resolution screens.
  • Changing the wording means exporting a new image, which slows down every campaign.
  • Extra images add download weight and can hurt load time on slow mobile connections.

A live-text button avoids all of this. The text stays sharp, it can be translated or edited in seconds, and it works with accessible email design because screen readers announce it as a link.

Three Coding Methods

MethodHow it worksPros and cons
Padding on the cellColour and padding on the td, link insideWorks everywhere; only the text is clickable in some Outlook versions

VML buttonv:roundrect in conditional commentsRounded corners in Outlook; more code

Many developers combine them: a padded cell for the shape, border on the link to fill the clickable area, and VML for Outlook rounding.

Method 1: Padding on the Cell

This is the simplest and most stable pattern. The table cell holds the colour, and the link sits inside it.

<table role="presentation" cellpadding="0" cellspacing="0" border="0"><tr><td bgcolor="#1a73e8" style="padding:14px 28px; border-radius:6px;"><a href="https://example.com" style="color:#ffffff; font-family:Arial, sans-serif; font-size:16px; text-decoration:none;">Shop the sale</a></td></tr></table>

The weak point is that only the words are clickable in some clients. A tap on the coloured edge does nothing.

Method 2: Border on the Link

To make the whole shape clickable, move the size onto the link. Outlook ignores padding on inline elements, but it does respect borders. So developers use a thick border in the same colour as the button.

<a href="https://example.com" style="background:#1a73e8; border:14px solid #1a73e8; border-left-width:28px; border-right-width:28px; display:inline-block; color:#ffffff; text-decoration:none;">Shop the sale</a>

This gives a fully clickable area in most clients, including classic Outlook, though line height can still vary slightly.

Method 3: VML for Rounded Outlook Buttons

Classic Outlook for Windows uses the Word engine, which ignores border-radius. If rounded corners are part of your brand, wrap a VML shape in conditional comments:

<!--[if mso]><v:roundrect xmlns:v="urn:schemas-microsoft-com:vml" href="https://example.com" style="height:48px; v-text-anchor:middle; width:200px;" arcsize="12%" stroke="f" fillcolor="#1a73e8"><center style="color:#ffffff; font-family:Arial, sans-serif; font-size:16px;">Shop the sale</center></v:roundrect><![endif]-->

Then wrap the normal HTML button in <!--[if !mso]><!--> and <!--<![endif]--> so Outlook shows only the VML version. The same VML approach is used for hero images; see our guide to Outlook background images with VML.

Button Design Rules

  1. Size: at least 44 px tall and 150 px wide; full width on mobile.
  2. Text: short and clear: "Shop the sale", "Book a call", "Track order".
  3. Contrast: at least 4.5:1 between text and button colour.
  4. One main button per email section, with a text link as a backup.
  5. Font: use a web-safe fallback so Outlook does not switch to Times New Roman.

On phones, a full-width button is easier to hit with a thumb. Use a media query to set the button table to width:100% under 600 px. If your layout does not adapt at all, start with our guide on why responsive emails fail on mobile.

Dark Mode and Buttons

Some clients invert or darken colours in dark mode. A light grey button with white text can end up nearly invisible. Pick a strong, mid-tone button colour that holds contrast on both white and dark backgrounds. Avoid pure black buttons, which can blend into a dark background. Test the button in Apple Mail, the Gmail app and Outlook with dark mode turned on.

Writing Button Text That Gets Clicks

The code makes a button work. The words make people want to press it. Good button text tells the reader exactly what happens next. "Shop the sale" is better than "Learn more", because the reader knows where they will land. Start with a verb, keep it to two to four words, and match the page the button opens. If the button says "Track order", the page should show the tracking details, not the home page.

Keep the label on one line on both desktop and mobile. Long labels wrap on small screens and make the button look broken. If you need extra context, put it in a short line of text above the button instead.

Accessibility Tips

  • Use real link text, not an empty link with a background image.
  • Do not rely on colour alone. The label should make sense on its own.
  • Keep enough space between two buttons so people do not tap the wrong one.
  • Add role="presentation" to layout tables so screen readers skip them and read only the link.

Common Mistakes

  • Using margin for spacing, which Outlook ignores.
  • Setting only border-radius and expecting Outlook to show rounded corners.
  • Putting the link only on the text, leaving the rest of the button dead.
  • Forgetting to update the link in both the VML and HTML versions, so Outlook users go to an old URL.
  • Setting a VML width too narrow, which wraps the text onto two lines.
  • Using vague labels like "Click here" that tell the reader nothing.

Frequently Asked Questions

What is a bulletproof button in email?

A button built from HTML and CSS instead of an image, so it displays and works even when images are blocked.

How do I make rounded buttons in Outlook?

Use a VML roundrect inside Outlook conditional comments. Classic Outlook ignores CSS border-radius. New Outlook uses a web engine and shows border-radius normally; see new Outlook vs classic Outlook.

How big should an email button be?

At least 44 px tall so it is easy to tap on a phone, with enough padding around the text.

Why is only the text of my button clickable?

The padding is on the table cell, not the link. Move the size onto the link using matching borders so the whole area is clickable.

Can I use a custom font on a button?

Yes, in clients that support web fonts. Always list a web-safe fallback like Arial, because classic Outlook will not load most web fonts.
