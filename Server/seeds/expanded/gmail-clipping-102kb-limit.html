Short answer: Gmail clips any email whose HTML code is larger than about 102 KB. Everything after that point is hidden behind a "[Message clipped] View entire message" link, which often hides your footer, unsubscribe link and tracking pixel. Images do not count, because they are hosted separately. The fix is to make the HTML itself smaller: remove unused code, repeated inline styles and heavy builder markup.

We see this problem constantly in templates made with drag-and-drop builders. It is one of the first things we check in our email testing and QA service. This guide explains what the limit is, what counts toward it, how to measure your email and how to bring the size down without changing the design.

Why Gmail Clipping Hurts Your Results

  • Hidden content: offers, products and calls to action below the cut are never seen by most readers. Few people click "View entire message".
  • Missing unsubscribe link: readers who cannot find it may mark you as spam instead, which damages deliverability.
  • Broken open tracking: the tracking pixel usually sits at the bottom, so clipped emails can under-report opens.
  • Legal footer out of sight: your company address and preference links sit in the footer, which is exactly the part that gets cut.

The worst part is that clipping is silent. Your email platform reports a normal send, and nothing warns you. You only find out if you open a real test in Gmail and scroll to the end.

What Counts Toward the 102 KB Limit

Only the HTML file size counts: tags, inline styles, comments, whitespace, hidden text and any code your email platform adds. Hosted images, fonts loaded from a URL and linked files do not count. Remember that your email platform (Klaviyo, Mailchimp, HubSpot) adds its own tracking and wrapper code when it sends, so aim for 80 to 90 KB of HTML to leave a safety margin.

Special characters matter too. Characters such as emoji or accented letters can take more than one byte each, and some platforms convert them to longer entity codes. This is rarely the main problem, but it adds up in long emails.

How to Check Your Email's Size

  1. Export or copy the final HTML from your email platform (the version it actually sends).
  2. Save it as a .html file and check the file size, or paste it into an HTML size checker.
  3. Send a real test to a Gmail inbox and scroll to the bottom. If you see "[Message clipped]", you are over the limit.

A quick way to see the size from a terminal is to save the file and run a byte count, for example wc -c email.html on Mac or Linux. The number is in bytes, so 102,000 bytes is roughly the limit. Always measure the sent version, not the file from your code editor, because the platform adds code on the way out.

8 Ways to Stay Under the Limit

  1. Minify the HTML before sending: remove line breaks, indentation and comments. This alone often saves 10 to 20%.
  2. Remove repeated inline styles. Builders repeat the same long style attribute on every element. Put shared styles in the head for clients that support them and keep inline styles short.
  3. Delete unused sections that are hidden with display:none. Hidden code still counts.
  4. Avoid pasting from Word or Google Docs, which adds large amounts of invisible markup.
  5. Keep Outlook fixes lean. MSO conditional code and VML are necessary, but only where they are needed.
  6. Use fewer, simpler tables. Deeply nested tables multiply code size quickly.
  7. Shorten long tracking links or use your platform's link tracking instead of adding many parameters by hand.
  8. Split very long emails into a shorter email plus a link to a landing page or blog post.

Example: trimming a repeated style

A builder might output this on every paragraph:

<td style="font-family:Arial, Helvetica, sans-serif; font-size:16px; line-height:24px; color:#333333; mso-line-height-rule:exactly; text-align:left; padding:0px 0px 0px 0px;">

A hand-coded version keeps only what the element needs and drops zero values:

<td style="font:16px/24px Arial,sans-serif;color:#333333;">

Across 60 or 80 cells, that difference is several kilobytes. Test shorthand in Outlook before relying on it everywhere, and keep the longer form where a client needs it.

Example: Outlook code only where needed

Wrap Outlook-only code in a conditional comment, such as <!--[if mso]> ... <![endif]-->, and use it once per section, not once per element. If you use background images, our guide to Outlook background images with VML shows a compact pattern.

Common Mistakes

  • Measuring the wrong file. The editor preview is smaller than what the platform sends.
  • Hiding a desktop and a mobile version of the same block. Both versions are in the code, so the size doubles.
  • Stacking product grids. Long product feeds with many columns grow fast. Show fewer items and link to the collection.
  • Leaving old sections in saved templates. Each campaign copied from the last one can carry dead code forward.
  • Base64 images. Images embedded as data in the HTML count toward the limit and can push an email over by themselves.

Builder Templates vs Hand-Coded Templates

A drag-and-drop template often reaches 120 to 200 KB because of wrapper code and repeated styles. A hand-coded template with the same design is usually 40 to 70 KB. A Short Real-World Scenario

A store sends a weekly newsletter with a hero, three editorial blocks and a twelve-product grid. The email looks fine in the builder. In Gmail, the last four products and the whole footer vanish behind "[Message clipped]". Checking the sent HTML shows it is well over the limit, mostly from repeated styles and a hidden mobile copy of the product grid. The fix is to rebuild the grid once with responsive stacking, trim the styles and cut the grid to eight products with a "Shop all" button. The email drops comfortably under 90 KB, and the footer is visible again. Long, content-heavy sends like this are where lean newsletter email templates pay off.

  • No base64 images and no hidden duplicate blocks.
  • Comments and whitespace removed.
  • Test opened in Gmail web and the Gmail app, scrolled to the end.
  • Unsubscribe link and address visible without clicking "View entire message".

Frequently Asked Questions

What is Gmail's email size limit?

Gmail clips messages when the HTML code exceeds about 102 KB. The rest of the message is hidden behind a "View entire message" link.

Do images count toward Gmail clipping?

No. Images hosted on a server are loaded separately and do not count. Only the HTML code, including inline styles and hidden content, counts. Images embedded as base64 data inside the HTML do count.

How do I stop Gmail from clipping my emails?

Reduce the HTML size: minify the code, remove repeated inline styles and hidden sections, and simplify nested tables. Aim for 80 to 90 KB to leave room for code your email platform adds.

Does clipping affect deliverability?

Indirectly, yes. If readers cannot find the unsubscribe link, some will click "Report spam" instead, and spam complaints hurt your sender reputation over time.

Does the Gmail app clip emails too?

Yes. Clipping applies in Gmail on the web and in the Gmail mobile apps, so check both when you test.
