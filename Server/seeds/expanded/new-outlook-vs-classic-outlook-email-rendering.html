Short answer: classic Outlook for Windows renders emails with the Microsoft Word engine, which supports very little modern CSS. New Outlook for Windows uses the same web-based engine as Outlook on the web, so it handles modern CSS much better. Microsoft is moving people to new Outlook, but many businesses will keep classic Outlook for years. For now, every email must work in both.

The simple way to think about it: classic Outlook is a word processor pretending to be a browser. New Outlook is a browser with some email-specific limits. Code that is valid in one can look very different in the other.

What Breaks Most Often in Classic Outlook

  • Width: max-width is ignored, so fluid layouts can stretch across the whole window unless you add a fixed-width ghost table.
  • Background images: CSS backgrounds disappear. You need VML, covered in our guide to Outlook background images with VML.
  • Rounded corners: buttons show as square boxes. See bulletproof email buttons for the VML roundrect method.
  • Spacing: margin and padding on some elements are ignored, and line height can add extra gaps.
  • Fonts: web fonts often fall back to Times New Roman unless you set a web-safe fallback in an MSO-specific style.
  • DPI scaling: on high-resolution screens, images and widths can scale unevenly.

What to Watch in New Outlook

New Outlook fixes most of the problems above, but it is not a normal browser. It filters some CSS and rewrites parts of your code, like other webmail clients. Some things to check:

  • Certain CSS properties and selectors may be stripped or rewritten.
  • Its dark mode adjusts colours on its own, which can change brand colours and logos. Our dark mode email design guide covers safe choices.
  • Your MSO conditional code is ignored, so the non-Outlook version of each element must look right on its own.

What Is Happening to Classic Outlook?

Microsoft is making new Outlook the default for Windows and Microsoft 365 users, and older standalone Office versions have already left support. Classic Outlook in Microsoft 365 is still available, and large companies often delay switching. So the Word engine will stay in your audience for some time, even as its share falls. Check your own email platform's client report to see how many readers still use it. Timelines can change, so check Microsoft's current announcements before planning around a date.

How to Code for Both

  1. Keep table-based layouts. They work in both engines.
  2. Keep MSO fixes (ghost tables, VML backgrounds and buttons) inside conditional comments. New Outlook ignores them, so they cause no harm.
  3. Use progressive enhancement: rounded corners and modern CSS for new Outlook, with a clean square fallback for classic.
  4. Test both versions separately. They can look very different. New Outlook also has its own quirks; see why new Outlook breaks some HTML emails.

Example: One Button, Two Engines

A button can carry both versions in one block:

<!--[if mso]> VML roundrect for classic Outlook <![endif]-->

<!--[if !mso]><!--> HTML link with border-radius for everyone else <!--<![endif]-->

Classic Outlook reads the first part only. New Outlook, Gmail and Apple Mail read the second part only. Each engine gets code it understands.

Example: Width Control

Wrap your fluid container in a fixed ghost table:

<!--[if mso]><table role="presentation" width="600"><tr><td><![endif]--> ... content ... <!--[if mso]></td></tr></table><![endif]-->

Classic Outlook holds the email at 600 px. New Outlook and phones use the fluid table inside. This also keeps your layout safe on mobile; see why responsive emails fail on mobile.

A Simple Plan for Teams

If you manage many templates, you do not need to fix everything at once. A step-by-step plan keeps the work under control:

  1. Check your data. Look at the email client report for the last few months. Note how many opens come from classic Outlook, new Outlook and Outlook on the web.
  2. List your templates. Start with the ones you send most: the newsletter, the welcome email and key transactional emails.
  3. Test each one in both versions. Take screenshots side by side and mark what breaks.
  4. Fix shared parts first. Headers, footers and buttons appear in every email, so one fix helps everywhere.
  5. Review again every few months. As more users move to new Outlook, your balance of fixes may change.

This approach avoids two extremes: dropping Outlook support too early, or spending hours on fixes that almost nobody sees.

Common Mistakes

  • Testing only in Outlook on the web and assuming classic Outlook looks the same.
  • Removing all MSO code after seeing a clean new Outlook preview.
  • Designing a hero that only works with a CSS background image.
  • Relying on a web font with no fallback.
  • Letting an email builder strip conditional comments on import.

Frequently Asked Questions

What is the difference between new Outlook and classic Outlook for emails?

Classic Outlook renders emails with Microsoft Word, which ignores most modern CSS. New Outlook uses a web engine like Outlook on the web and supports much more CSS.

Do I still need Outlook fixes in my email code?

Yes, as long as part of your audience uses classic Outlook. The fixes sit in conditional comments that new Outlook ignores.

Is classic Outlook going away?

Microsoft is moving users to new Outlook, but classic Outlook remains in use, especially in businesses. Check your own client data before dropping support.

How can I tell which Outlook my readers use?

Check the email client report in your sending platform. Some platforms group Outlook versions together, so a testing tool that separates them can help.

Does new Outlook on Mac use the same engine?

Outlook for Mac has its own engine and has never used Word for rendering. Test it as a separate client.
