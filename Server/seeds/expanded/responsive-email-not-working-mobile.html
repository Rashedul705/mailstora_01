Short answer: an email looks broken on mobile when it has a fixed width, no viewport meta tag, columns that do not stack, or text and buttons that are too small. The fix is a fluid layout: tables with width="100%" and a max-width of about 600 px, columns that stack with media queries or a hybrid method, text of at least 14 px and buttons at least 44 px tall.

Signs Your Email Is Not Responsive

  • The reader has to zoom or scroll sideways.
  • Text is tiny and buttons are hard to tap.
  • Two or three columns squeeze next to each other.
  • Images spill past the screen edge.
  • Spacing looks huge on one side and cramped on the other.

Many people read email on a phone first. If the first view is hard to read, they often delete the email rather than zoom in. So mobile problems cost clicks even when the desktop version looks perfect.

Why It Happens

Email is not like a web page. There is no single browser. Each email client, such as Apple Mail, the Gmail app, Outlook for iOS and Samsung Mail, has its own rules about which CSS it supports. A layout that relies on one feature, such as media queries, may work in one app and fail in another. That is why good email code has more than one layer of protection.

6 Fixes

  1. Add the viewport tag: <meta name="viewport" content="width=device-width, initial-scale=1">.
  2. Use fluid tables: width="100%" with a centered container of max-width:600px. For Outlook, wrap it in a fixed 600 px ghost table.
  3. Stack columns: use media queries to make columns full width under 600 px. For Gmail apps that ignore media queries, use the hybrid (fluid inline-block) method.
  4. Make images fluid: set width attribute plus max-width:100%; height:auto.
  5. Size text for phones: body text 14 to 16 px, headings 22 px or more.
  6. Make buttons tappable: at least 44 px tall and full width on mobile. See bulletproof email buttons.

Fix 2 in Detail: The Fluid Container

A typical container looks like this:

<!--[if mso]><table role="presentation" width="600" align="center"><tr><td><![endif]-->

<table role="presentation" width="100%" style="max-width:600px; margin:0 auto;">...</table>

<!--[if mso]></td></tr></table><![endif]-->

Phones get a table that shrinks to fit. Classic Outlook, which ignores max-width, gets the fixed 600 px ghost table instead. Without the ghost table, Outlook can stretch the email across the whole window. The difference between new and classic Outlook explains why this is still needed.

Fix 3 in Detail: Media Queries vs Hybrid

A media query stacks columns like this:

@media screen and (max-width:600px) { .column { width:100% !important; display:block !important; } }

This works in Apple Mail and many other apps. But some Gmail setups, such as certain third-party accounts in the Gmail app, may strip the style block. The hybrid method solves this. Each column is a div with display:inline-block, a max-width such as 300 px, and width:100%. When the screen is too narrow for two columns, the second one wraps below the first with no media query needed. Use media queries as an extra layer on top.

Fix 4 in Detail: Images

Write images like this: <img src="hero.jpg" width="600" alt="New spring range" style="display:block; width:100%; max-width:600px; height:auto;">. The width attribute keeps Outlook from showing the image at its full file size. The inline CSS lets it shrink on phones.

Why Builders Sometimes Get This Wrong

Some editors lock widths in pixels or produce nested tables that do not stack. Pasting designs from Canva or a Word document as one large image also breaks on mobile. Mobile-First Design Habits

Code can only do so much if the design itself does not fit a phone. A few habits at the design stage save a lot of fixing later:

  • Design the mobile view too. Ask for a mobile mockup, not only a desktop one, so the developer knows how each section should stack.
  • Keep the key message near the top. On a phone, the first screen shows only the header and a little more.
  • Avoid text inside images. It shrinks with the image and becomes hard to read.
  • Use generous line height. Around 1.4 to 1.6 makes body text easier to read on small screens.
  • Leave space around links. Links that sit too close together are easy to mis-tap.

When the design already follows these habits, the code stays simpler and there are fewer surprises across clients.

Common Mistakes

  • Setting width="600" on every inner table, so nothing can shrink.
  • Putting all layout CSS in the <style> block, so it fails when a client strips it.
  • Using a single image for the whole email, which makes text unreadable on a phone.
  • Forgetting height:auto, which stretches images out of shape.
  • Placing two buttons side by side with no room between them on small screens.
  • Testing only in a desktop browser preview instead of on a real phone.

Frequently Asked Questions

Why does my email look tiny on my phone?

The email probably has a fixed width and no viewport meta tag, so the phone shrinks the whole desktop layout to fit.

Do media queries work in Gmail?

Gmail supports media queries in many cases, but not all Gmail apps and account types. The hybrid method stacks columns without media queries.

What width should an email be?

Around 600 to 640 px on desktop, and 100% width on mobile.

Why do my images overflow the screen on mobile?

They have a fixed pixel width in CSS and no max-width:100%. Keep the width attribute for Outlook, but add fluid CSS for phones.

Is a single-column layout better for mobile?

It is the simplest and safest choice. Multi-column layouts are fine if they stack cleanly on small screens.
