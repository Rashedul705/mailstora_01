Why AI Email Code Breaks

Most AI models learned HTML from websites. Email is a different world. Email clients use older, stricter and very different rendering engines, and each one strips or rewrites code in its own way. So an AI tool will often produce code that looks perfect in a browser preview and then falls apart in an inbox. Here are the most common reasons.

  • Web layouts, not email layouts. Flexbox and grid work in browsers but not in classic Outlook, which uses Microsoft Word to render HTML. Columns collapse, widths are ignored and elements stack in odd ways.
  • No MSO fixes. Ghost tables, VML backgrounds and bulletproof buttons are usually missing. See background images in Outlook and bulletproof email buttons.
  • Styles not inlined. Some clients strip or change head styles. AI tools often write a neat <style> block and a few classes, which is exactly what gets lost. See new Outlook issues.
  • Heavy code that pushes past Gmail's 102 KB limit. Repeated wrappers, comments and unused CSS add up fast.
  • No dark mode or accessibility work. Logos disappear on dark backgrounds, and images have empty or missing alt text. See dark mode and accessible email design.
  • Not platform-ready. Missing Klaviyo, Mailchimp or HubSpot editable tags, so your marketing team cannot change text or images without touching code.

A typical example

Ask a chatbot for a two-column product email and you may get something like this:

<div style="display:flex; gap:20px"><div class="col">...</div><div class="col">...</div></div>

It looks fine in Chrome. In classic Outlook, display:flex and gap are ignored, so the two columns stack at full width. In some webmail clients the .col class is renamed and its styles never apply. An email-safe version uses a table with fixed widths and inline styles:

<table role="presentation" width="600" cellpadding="0" cellspacing="0" border="0"><tr><td width="290" valign="top" style="padding:0 10px 0 0">...</td><td width="290" valign="top">...</td></tr></table>

For mobile stacking you then add a hybrid or media query approach, plus an Outlook ghost table. That extra layer is what most AI drafts leave out.

How to Use AI Well

AI is not useless for email. It is fast, and it is good at some parts of the job. The trick is to use it where it is strong and check it where it is weak.

  1. Ask for table-based HTML with inline styles and Outlook conditional comments. Say it plainly in your prompt: "Use nested tables, no flexbox or grid, inline all CSS, max width 600px, include MSO conditional comments."
  2. Use AI for copy, subject lines and layout ideas, where it helps most. It can give you ten subject lines or three hero headline options in seconds.
  3. Run the output through an inliner and check the file size. Remove comments and unused styles before you send.
  4. Test in classic Outlook, Gmail, Apple Mail and on mobile with our testing checklist.
  5. Add your platform's editable tags so the team can edit it later. In Klaviyo, see custom HTML templates in Klaviyo.

Prompt template you can reuse

A clear prompt gives a cleaner first draft. Something like: "Write an HTML email for a 600px layout. Use only tables for layout with role="presentation". Inline all CSS. Use web-safe fonts with fallbacks. Add alt text for every image. Include a bulletproof button that works in Outlook. Keep the file under 60 KB." This will not make the code perfect, but it avoids many basic mistakes.

Common Mistakes When Shipping AI Templates

  • Trusting the browser preview. A browser is not an email client. Always send real tests.
  • Copying text into images. Some AI design tools output the whole email as one image. It will be blocked by default in some clients, is bad for accessibility and can hurt deliverability.
  • Forgetting the plain-text part. Many platforms create it for you, but check it reads well.
  • Pasting code into a drag-and-drop text block. The editor may rewrite it and break the layout.
  • Skipping links and tracking checks. AI often leaves placeholder links like href="#".

Frequently Asked Questions

Can ChatGPT or other AI tools make HTML email templates?

They can create a draft, but the code often lacks Outlook support, inline styles and platform tags, so it needs fixing and testing before you send it to customers.

Why does my AI-generated email break in Outlook?

It usually uses divs, flexbox or modern CSS that classic Outlook's Word engine does not support. Tables, fixed widths and conditional comments are needed.

Is AI going to replace email developers?

AI speeds up drafts and copy, but reliable rendering across clients still needs email-specific knowledge and testing in real inboxes.

How can I make AI produce better email code?

Ask for table-based layouts, inline CSS, a 600px width, alt text and Outlook conditional comments. Then inline, check the file size and test anyway.

Is it safe to send an email that is one big image?

It is not a good idea. Images can be blocked, screen readers cannot read them, and image-only emails can look like spam. Use live text for key messages.
